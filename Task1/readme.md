# Задача 1
a. Проработайте конфигурацию развёртывания приложения в Kubernetes. 
На каждой площадке будет использоваться отдельный kubernetes кластер.
Это повышает доступность и уменьшает зависимость. 
Учитывая что расположение будет в разных регионах выбрана схема именно независимых кластеров т.к. возможны большие задержки при их общение.
Так же отдается предпочтение горизонтальному масштабированию инстансов приложения. Для базы данных будет предусмотрена вертикальная масштабируемость.
b. Спланируйте балансировку нагрузки. 
Будет использоваться geo load balancer для распределения нагрузки по ближайшим площадкам. Это разделит пользователей между площадками и повысит скорость отклика.
Внутри площадки будет локальный load balancer по разным pod приложения.
c. Определите наиболее подходящую фейловер-стратегию.
Будет использоваться Active-Active, обе площадка параллельно обрабатывают запросы. При отказе одной, нагрузку будет переведена на остальные рабочие.
d. Определите конфигурацию базы данных. 
Шардирование не используется т.к. размер базы данных всего 50 гб.
Для распределенной работы базы postgres будет использоваться Patroni, он позволит автоматически управлять репликацией и failover между кластерами.
Так же будет репликация по схеме Primary-StandBy с асинхронной репликацией. В случае сбоя нагрузка будет сразу переведена на реплику.
Предусматривается регулярные backup 1 раз в день на object storage, и снепшоты базы данных 4 раза в сутки.
